# 🔍 Lost & Found Portal

A modern, real-time web application designed to connect people who have lost their belongings with those who have found them. The portal streamlines the recovery process using a smart matching engine, interactive geo-location tagging, secure claim verification, live notifications, and real-time messaging.

---

## 🌟 Key Features

*   **🤖 Smart Auto-Matching:** An automated matching engine compares lost and found listings on creation and alerts users to high-probability matches based on category, location, and keywords.
*   **📍 Geo-Location Tagging:** Pinpoint exact locations on an interactive map. Filter and search lost or found items by geographic proximity.
*   **💬 Real-Time Chat:** A secure messaging channel powered by WebSockets (Socket.IO) that allows finders and claimants to communicate directly to coordinate safe returns.
*   **🔒 Secure Claim Verification:** Protects owner items. Claimants upload evidence (images, purchase receipts, distinct markings) and describe proof of ownership which must be approved by the reporter or admin.
*   **⚡ Instant Live Notifications:** Real-time push updates for match alerts, claim approvals/rejections, and new messages.
*   **🛡️ Robust Admin Console:** High-level overview to manage item reports, categorize items, monitor flags, handle security reports, and control site access.
*   **☁️ Cloudinary Integration:** Supports multiple image attachments per listing, stored securely and served fast via Cloudinary CDN.

---

## 🛠️ Tech Stack

*   **Backend:** Python 3, Flask, Flask-SocketIO, Gunicorn, Eventlet (production WebSocket worker)
*   **Database:** MySQL 8.x (compatible with Aiven Cloud DB, MySQL local/RDS)
*   **Frontend:** HTML5, CSS3 (Vanilla CSS with dynamic grid & flex layouts), Javascript (ES6), Socket.IO Client, FontAwesome 6
*   **CDN & Media Storage:** Cloudinary Image Upload API

## 🏗️ Database Schema

The database relies on an `InnoDB` MySQL layout structured around 9 main tables:

1.  `users`: Stores credentials (bcrypt hashed), profiles, roles (user/admin), and OAuth connection IDs.
2.  `categories`: Custom icons, sort weights, and color HEX values managed by administrators.
3.  `items`: The central table representing reports (lost vs found), coordinates, category mapping, and state values.
4.  `item_images`: URLs to images stored on Cloudinary linked to item reports.
5.  `claim_requests`: Pivot table between item, finder, and claimant, mapping proof files and approval states.
6.  `conversations`: Ties item claimants and item finders together into chat rooms.
7.  `messages`: Live chat message logs with read/unread statuses.
8.  `notifications`: Notification queue with type classifications (`new_claim`, `claim_approved`, etc.).
9.  `item_matches`: Matches generated by the background auto-matcher scoring script.

## ⚙️ Quick Start & Installation

### Prerequisites
*   Python 3.8+
*   MySQL Server 8.x
*   Node.js (for managing MCP development assets if needed)
*   Cloudinary Account (Free tier)

### 1. Clone the Repository
```bash
git clone https://github.com/solunkepranav/lost-and-found.git
cd lost-and-found
```

### 2. Set Up Virtual Environment & Dependencies
Create a virtual environment and install package dependencies:
```bash
# Windows
python -m venv venv
venv\Scripts\activate

# macOS/Linux
python3 -m venv venv
source venv/bin/activate

# Install requirements
pip install -r requirements.txt
```

### 3. Install Frontend Dependencies
```bash
npm install
```

### 4. Configure Environment Variables
Copy `.env.example` into a new `.env` file and fill in your database, Socket.IO, and Cloudinary credentials:
```bash
cp .env.example .env
```

### 5. Initialize the Database
Run the setup script to establish the MySQL schema and inject seed mock data for development:
```bash
# Create schema and insert sample mock data
python init_db.py

# Optional: To drop the existing database and start completely fresh
python init_db.py --drop
```

### 6. Run the Application
Run Flask locally:
```bash
python app.py
```
Open your browser and navigate to `http://127.0.0.1:5000` to access the portal.

## 🔒 Security & Moderation

-   **Passwords:** Securely hashed using `bcrypt` before storage.
-   **Uploads:** Strict file-type filtering on image attachments before routing to Cloudinary.
-   **Ownership Verification:** Multi-stage claims verify owner descriptions and proof images prior to closing listings.
-   **Session Guard:** Custom `@login_required` decorators ensure route safety and permission levels.
